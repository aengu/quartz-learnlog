- **`prefetch_related`(**lookups*)**
    
    아래 공식문서를 정리한 내용입니다.
    
    [Django](https://docs.djangoproject.com/en/4.1/ref/models/querysets/#prefetch-related)
    
    - 각 지정된 룩업에 대한 관련 객체를 한번에 자동으로 가져오는 쿼리셋을 반환한다.
    - 관련된 객체를 접근함으로써 발생하는 쿼리의 쇄도를 방지하기 위해 사용함으로써 select_related와 목적은 비슷하다. 하지만 전략은  다르다.
    - select_related는 sql join을 생성하고, select문에 관련된 객체의 fields를 포함함으로써 작동한다. 이러한 이유로 select_related는 관련된 객체를 동일한 데이터베이스 쿼리에서 가져온다. 하지만, 다대다 관계를 건너뛰며 조인을 수행하는 것이 더 큰 결과 집합을 초래할 수 있으므로, select_related는 foreign key 및 one to one과 같은 단일 값 관계에 한정된다.
    - 반면 prefetch_related는 각 관계에 대해 별도의 조회를 한다. 그리고 파이썬 안에서 joining을 한다.
    - 이로써 select_related로는 할 수 없는 m2m, m2o 객체를 미리 가져올 수 있다.
    - foreign key와 o2o관계도 물론 가능하지만 결과를 동일한 유형으로 제한해야 한다.
    - 예제1
        
        ```python
        class Topping(models.Model):
            name = models.CharField(max_length=30)
        
        class Pizza(models.Model):
            name = models.CharField(max_length=50)
            toppings = models.ManyToManyField(Topping)
        
            def __str__(self):
                return "%s (%s)" % (
                    self.name,
                    ", ".join(topping.name for topping in self.toppings.all()),
                )
        
        class Restaurant(models.Model):
            pizzas = models.ManyToManyField(Pizza, related_name='restaurants')
            best_pizza = models.ForeignKey(Pizza, related_name='championed_by', on_delete=models.CASCADE)
        ```
        
        위와 같은 관계에서, 모든 pizza 객체를 print하고 싶다면 다음과 같이 코드를 작성할 수 있다.
        
        - 예제 데이터셋 만들기
            
            ```python
            import random
            from django.db import transaction
            @transaction.atomic
            def test_set1():
                topping_names = ['파인애플', '감자', '고구마', '불고기', '새우']
                pizzas_names = ['클래식피자', '씬피자', '바이트피자', '시카고피자']
            
                for name in topping_names:
                    Topping.objects.create(name = name)
            
                toppings = list(Topping.objects.all())
                for name in pizzas_names:
                    included_toppings = random.sample(toppings,2)
                    p = Pizza.objects.create(name=name)
                    p.toppings.set(included_toppings)
            
            @transaction.atomic
            def test_set2():
                pizzas = list(Pizza.objects.all())
                for _ in range(4):
                    best_pizza = random.sample(pizzas,1)[0]
                    r = Restaurant.objects.create(best_pizza = best_pizza)
                    r.pizzas.set(random.sample(pizzas,2))
            ```
            
        
        ```python
        from django.test.utils import CaptureQueriesContext
        from django.db import connection
        def test_check_prefetch_related():
        
            with CaptureQueriesContext(connection) as num_queries:
                pizzas = list(Pizza.objects.all())
                print('전체 피자 수:', len(pizzas), pizzas)
                print('.all()의 쿼리 수: ', len(num_queries.captured_queries))
        	
            with CaptureQueriesContext(connection) as prefetched_num_queries:
                print(list(Pizza.objects.prefetch_related('toppings')))
                print('.prefetch_related()의 쿼리 수: ', len(prefetched_num_queries.captured_queries))
        ```
        
        ```python
        전체 피자 수: 4
        .all()의 쿼리 수:  5
        .prefetch_related()의 쿼리 수:  2
        ```
        
        - num_queries: all() 한번, 4개 피자 순회하며 __str__에서 매번 쿼리해서 총 5번
        - prefetched_num_queries: 피자 불러오기 한번, 대응하는 toppings 가져오기 한번, 이후 4개 피자 순회할땐 캐싱된걸 재사용해서 쿼리하지 않는다.
    - queryset과 마찬가지로, 다른 database query를 의미하는 chained method가 뒤에 이어질 경우, 전에 캐싱된 결과는 무시하고 새로 database query를 사용해서 데이터를 얻을 것이다.

    - to_attr: 사전 로드된 결과를 사용자 정의 속성에 할당할 수 있다. 결과는 리스트에 저장된다.
        
        ```python
        >>> prefetch_object = Prefetch('championed_by', to_attr = 'to_restaurant')
        >>> pizzas = Pizza.objects.prefetch_related(prefetch_object)
        >>> first_pizza = pizzas.get()
        
        >>> first_pizza.to_restaurant
        [<Restaurant: Restaurant object (3)>]
        ```
        
        이렇게 prefetch할 때의 룩업을 사용자가 속성으로 정의할 수 있다.

- prefetch_related, selected_related 함께 쓰는 경우
    
    ```python
    Model.objects
    	.filter(조건절)
    	.select_related('정방향 참조 필드') # 해당 필드를 join해서 가져온다.
    	.prefetch_related('역방향 참조 필드') # 해당 필드는 추가쿼리로 가져온다.
    
    '''
    inner / outer 여부는 QuerySet 조건절 변경에 따라 join 옵선이 변할 수 있음.
    일반적으로 ForignKey(null = True)이면 outer join,
    ForignKey(null=False)이면 Inner join
    '''
    ```
    
    ```sql
    select * from 'Model' = 
    (inner OR left outer) join '정방향 참조 필드' r on.m.r_id = r.id
    'where 조건절';
    
    select * from '역방향 참조 필드' where id in ('첫번째 쿼리 결과의 id 리스트');
    ```
