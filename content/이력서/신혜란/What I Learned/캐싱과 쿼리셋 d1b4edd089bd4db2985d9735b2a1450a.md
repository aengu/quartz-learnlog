- **QuerySet은 데이터베이스 접근을 최소화 하기 위해 캐시를 갖고 있다 → QuerySet._result_cache**
- 새로 생성된 쿼리셋의 캐시는 비어있다. 쿼리셋이 처음 계산되면 데이터베이스 쿼리가 발생하고, django는 쿼리 결과를 쿼리셋의 캐시에 저장하고 명시적으로 발생된 결과(예: 쿼리셋이 반복되는 경우의 다음 요소)를 반환한다.
- 이후 쿼리셋을 계산하는 경우, 캐시된 결과를 재사용한다
    
    ```bash
    >>> users: QuerySet = User.objects.filter(id__lte=30)
    >>> users._result_cache
    ```
    
    users라는 쿼리셋을 생성하고 캐시를 확인, 당연히 비어있다.
    
    ```bash
    >>> list(users)
    ```

    쿼리셋을 계산하고 다시 캐시를 확인했더니, 쿼리 결과가 저장되어 있다.
    
    ```bash
    >>> users[0]
    <User: username1>
    >>> users[1]
    <User: username2>
    ```
    
    이후 쿼리셋의 요소를 확인할 때도, 별도의 쿼리없이 저장된 캐시를 사용하고 있다.
    
- 쿼리셋이 캐시되지 않는 경우
    
    쿼리셋은 항상 결과를 캐시하지는 않는다. 
    
    - **쿼리셋의 일부만 평가할 경우**, 캐시는 체크되지만, 캐시가  후속쿼리에 의해 반환되는 요소는 캐시되지 않는다 → 특히 [:]나 인덱스로 쿼리셋을 제한하면 **캐시가 채워지지 않는다. (신기한건 [:]는 캐싱이 안되는데, [:::]는 캐싱이 된다..)**
    - 예를들어 반복적으로 쿼리셋의 특정 인덱스를 반복적으로 가져오는 것은 데이터베이스에 매번 쿼리를 하게 된다.
    - 예시: 쿼리셋의 일부만 평가할 경우: 특정 인덱스를 반복적으로 가져오는 경우
        
        ```bash
        >>> users = User.objects.filter(id__lte=30)
        >>> users[0]
        SELECT "orm_practice_app_user"."id",
               "orm_practice_app_user"."password",
          FROM "orm_practice_app_user"
         WHERE "orm_practice_app_user"."id" <= 30
         LIMIT 1
        
        Execution time: 0.037982s [Database: default]
        <User: username1>
        
        >>> users[1]
        SELECT "orm_practice_app_user"."id",
               "orm_practice_app_user"."password",
          FROM "orm_practice_app_user"
         WHERE "orm_practice_app_user"."id" <= 30
         LIMIT 1
        OFFSET 1
        
        Execution time: 0.006432s [Database: default]
        <User: username2>
        
        >>> users._result_cache
        >>>
        ```
        
        쿼리셋의 특정 인덱스를 가져올 때마다 쿼리를 하는데, limit를 사용해 필요한 만큼만 가져오는 것을 확인할 수 있다 → **쿼리셋의 일부만 평가해서 캐싱되지 않았기 때문에 result_cache가 비어있어 매번 질의를 하게 되는 것**
        
    - +) 전체 쿼리셋을 평가하는 경우 (전체 interation: list, bool …)
        
        ```python
        def i_am_function_view7(request: WSGIRequest):
            users1: QuerySet = User.objects.filter(id__lte=30)
            print(users1)
            print('print()의 result_cache: ', users1._result_cache)
        
            users2: QuerySet = User.objects.filter(id__lte=30)
            users2.__repr__()
            print('__repr__()의 result_cache: ', users2._result_cache)
        
            users3: QuerySet = User.objects.filter(id__lte=30)
            bool(users3)
            print('bool()의 result_cache: ', users3._result_cache)
        
            users4: QuerySet = User.objects.filter(id__lte=30)
            list(users4)
            print('list()의 result_cache: ', users4._result_cache)
        
        		return HttpResponse(content="", content_type="application/json")
        ```
        
        ```bash

        __repr__()의 result_cache:  None
        ```

        print와 repr은 전체 쿼리셋을 평가하지 않고 limit 21으로 제한을 두기 때문에 캐싱되지 않는다.
