내부적으로, queryset은 데이터베이스에 hit 없이 구성될 수도, filtered, sliced될 수도, 일반적으로 전달될 수 있다. 그 어떤 데이터베이스도 사용자가 어떤 쿼리셋을 계산하기 전까진 실제로 활동을 발생하지 않는다. (lazy loading)

1. **iteration**.
    
    queryset은 반복 가능하다. 이 쿼리셋은 당신이 처음 반복을 할 때 데이터베이스에 쿼리가 실행된다. 
    
    ```python
    for e in Entry.objects.all():
        print(e.headline)
    ```
    
2. **Asynchronous iteration**
    
    **쿼리셋은 비동기를 사용하여 반복이 가능하다.**
    
    ```python
    async for e in Entry.objects.all():
      results.append(e)
    ```
    
    동기, 비동기 반복은 동일한 기본 캐시를 공유한다고 하는데 이건 뭔지 잘 모르겠다. 비동기 캐시는 이번 4.1에서 처음 추가된듯?
    
3. **Slicing**
    
    쿼리셋은 파이썬의 array slicing syntax([:])로 자르기가 가능하다. 미실행한 쿼리셋을 자르면 미실행된 또다른 쿼리셋을 반환한다. 하지만 django에선 [::step] step 파라미터로 자르면 쿼리가 실행되고 list를 반환할 것이다. 실행된 쿼리셋을 자르는 것 또한 실행되어 list를 반환할 것이다.
    
    - 예제
        
        **신기한건 [:]는 캐싱이 안되는데, [:::]는 캐싱이 된다..**
        
        ```bash
        >>> b = User.objects.filter(id__lte = 30)
        >>> c = b[:3]
        >>> d = b[::1]
        SELECT "orm_practice_app_user"."id",
               "orm_practice_app_user"."password",
        FROM "orm_practice_app_user"
        WHERE "orm_practice_app_user"."id" <= 30
        
        >>> type(d)
        <class 'list'>
        >>> type(c)
        <class 'django.db.models.query.QuerySet'>
        >>> type(b)
        <class 'django.db.models.query.QuerySet'>
        ```
        
    
    더불어 미실행한 쿼리셋을 자르면 미실행한 또다른 쿼리셋이 반환되지만, 추가로 수정(filter 추가, 순서 변경)은 불가능하다. 미실행한 쿼리셋을 변경하면 더이상 의미가 명확하지 않아 sql로 번역할 수 없기 때문.
    
    - 예제 AssertionError: Cannot filter a query once a slice has been taken.
        
        ```bash
        >>> a = User.objects.filter(id__lte = 30)
        >>> b = a[:3]
        >>> b.filter(id__gte = 5)
        Traceback (most recent call last):
          File "<console>", line 1, in <module>
          File "sql_practice/Django_ORM_pratice_project/.venv/lib/python3.9/site-packages/django/db/models/query.py", line 941, in filter
            return self._filter_or_exclude(False, args, kwargs)
        Django_ORM_pratice_project/.venv/lib/python3.9/site-packages/django/db/models/query.py", line 953, in _filter_or_exclude
            assert not self.query.is_sliced, \
        AssertionError: Cannot filter a query once a slice has been taken.
        ```
        
    
4.  **Pickling/Caching.** 
    - pickling querysets
        
        [Making a Pickle field in Django models](https://www.tutorialspoint.com/making-a-pickle-field-in-django-models)
        
        pickling: python object를 binary code로 직렬화/역직렬화하는 것
        
        당신이 queryset을 pickle한다면, 강제적으로 모든 결과를 메모리에 load할 것이다. pickling은 보통 캐싱을 precursor하는데에 사용된다. 캐시된 쿼리셋을 reload할 때, 
        
        If you [**`pickle`**](https://docs.python.org/3/library/pickle.html#module-pickle)
         a **`QuerySet`**
        , this will force all the results to be loaded into memory prior to pickling. Pickling is usually used as a precursor to caching and when the cached queryset is reloaded, you want the results to already be present and ready for use (reading from the database can take some time, defeating the purpose of caching). This means that when you unpickle a **`QuerySet`**
        , it contains the results at the moment it was pickled, rather than the results that are currently in the database.
        
    
     **Pickling/Caching.** See the following section for details of what is involved when [pickling QuerySets](https://docs.djangoproject.com/ko/4.1/ref/models/querysets/#pickling-querysets). The important thing for the purposes of this section is that the results are read from the database.
    
5. **repr(), len(), list(), bool()**
    - repr()은 무엇인가?
        
        [django annotate unexpected limit 21](https://stackoverflow.com/questions/60797028/django-annotate-unexpected-limit-21)
        
        콘솔에서 쿼리를 실행하면 limit 21 이라는 예상밖의 구문을 볼 수 있다.
        
        ```bash
        >>> a = User.objects.all()
        >>> a
        SELECT "orm_practice_app_user"."id",
               "orm_practice_app_user"."password",
          FROM "orm_practice_app_user"
         LIMIT 21
        
        Execution time: 0.024462s [Database: default]
        <QuerySet [<User: username1>, <User: username2>, <User: username3>, <User: username4>, <User: username5>, <User: username6>, <User: username7>, <User: username8>, <User: username9>, <User: username10>, <User: username11>, <User: username12>, <User: username13>, <User: username14>, <User: username15>, <User: username16>, <User: username17>, <User: username18>, <User: username19>, <User: username20>, '...(remaining elements truncated)...']>
        ```
        
        콘솔에 쿼리를 직접 실행하거나, print로 출력하는 등 → 쿼리 결과를 즉시 확인하는 경우, QuerySet의 기본 내장함수 __repr__()을 실행한다. 편의를 위해 `REPR_OUTPUT_SIZE` 으로 결과를 제한한다. (default값은 21이다)
        
    
    bool()과 마찬가지로 if문, and, or같은 **연산자**에 쓰인 경우도 마찬가지이다.
    
    메서드에 따라 또 다른 쿼리셋의 반환여부가 다르니 한 번쯤 읽어두자.
    
    - **Methods that return new `QuerySets`**
        - filter, annotate, order_by, values, values_list, all, selected_related, prefetch_related …
    - **Methods that do not return new `QuerySets`**
        - get, create, bulk_create, iterator, aggregate ,exists, count …
