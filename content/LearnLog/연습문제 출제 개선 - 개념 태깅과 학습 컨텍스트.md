# 연습문제 출제 개선 - 개념 태깅과 학습 컨텍스트

> 출제할 때 개념·사고 유형·추정 난이도를 함께 저장하고, 학습 자료는 코드와 조건이 끊기지 않도록 구성했다. 개념별 숙련도 모델링에 필요한 준비 단계이며, BKT 자체는 아직 적용하지 않았다.

## 왜 바꿨나

기존 문제는 실행 추적 형태에 치우쳐 있었고, 어떤 개념을 확인하는 문제인지 명시적인 정보가 부족했다. 학습 자료도 앞부분만 자르면 코드나 예외 조건이 빠질 수 있었다.

## 출제와 태깅

새 선택지 문제는 자료에 맞춰 **개념 구분·상황 적용·실행 추적** 중 적합한 형태로 출제한다. 유형을 억지로 섞지는 않는다.

각 step에는 다음 정보를 저장한다.

| 항목 | 용도 |
| --- | --- |
| `concept_id` 또는 `concept_candidate` | 등록된 개념 연결 또는 새 개념의 이름·설명 제안 |
| `cognitive_type` | 개념 구분 / 상황 적용 / 실행 추적 |
| `estimated_difficulty` | 출제 시 추정한 easy / medium / hard |
| `distractors` | 오답 유형과 해당 보기가 틀린 이유 |

`Concept`은 관리자가 검토해 등록하는 개념 사전이다. 관련 개념을 최대 10개 제공하고, 사전에 없으면 후보만 남긴다. **후보를 자동 등록하거나 같은 이름끼리 자동 병합하지 않는다.** 기존 문제 JSON도 일괄 변경하지 않는다.

## 학습 컨텍스트

- Markdown을 우선 사용하고, 없으면 원문 답변을 사용한다.
- 참고 자료 목록은 공식문서 URL 1개로 정리한다. URL 본문을 추가로 가져오지는 않는다.
- 최대 6,000자 안에서 전달하되, 긴 자료는 섹션 단위로 선택하고 조건·예외를 우선한다.
- 코드·설명·후속 조건을 중간에서 자르지 않는다. 너무 큰 섹션은 통째로 제외한다.
- 닫히지 않은 코드 블록이나 보존 가능한 섹션이 없는 자료는 출제 실패로 처리한다.
- `_generation`에 프롬프트 버전, 입력 길이, 생략 섹션 수, 제공 개념 ID를 남긴다.

단순히 입력을 줄이는 최적화는 아니다. 기존 앞부분 절삭보다 길어질 수 있지만, 문제를 만드는 데 필요한 맥락을 보존하는 쪽을 택했다. 큰 코드 섹션이 제외될 수 있다는 한계는 남아 있다.

## 검증과 다음 단계

태그 구조·보기 중복·정답 인덱스와 답안의 일치 등을 코드와 테스트로 검증한다. 다만 **형식 검증이 기술적 사실성이나 정답의 유일성까지 보장하지는 않는다.** 난이도와 오답 설명도 측정된 난이도·확정된 오개념 진단이 아니라 출제 모델의 추정이다.

러닝메이트에는 질문과 보기만 전달하고 정답·태그·오답 해설은 제외한다. 다음은 실제 문항의 개념 연결 품질을 확인한 뒤, 풀이 시간 수집과 BKT 숙련도 갱신으로 이어갈 예정이다.

관련 구현: `practice/services/exercise_prompt.py`, `exercise_context.py`, `exercise_service.py`, `practice/models.py`, `practice/tests/test_exercise_authoring.py`.
